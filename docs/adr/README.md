# Architecture Decision Records

Une ADR fixe contexte, décision, conséquences et alternatives d'un choix structurel.
Les statuts sont proposée, acceptée, remplacée ou abandonnée. Une ADR acceptée n'implique pas que
son code existe déjà. Conserver l'historique et relier une ADR remplacée à la suivante.

- [0001 — Monolithe modulaire](0001-modular-monolith.md), acceptée dans le brief.
- [0002 — Modèle temporel événementiel](0002-event-driven-time-model.md), acceptée, implémentation future.
- [0003 — UI web responsive](0003-responsive-web-ui.md), acceptée.

- [0004 — Première persistance](0004-world-persistence.md), acceptée aux étapes 1–2.

Nouvelles ADR numérotées séquentiellement ; date de rédaction 2026-10-28 pour ces trois entrées.
Les détails de gameplay non arbitrés restent dans le [registre](../05-project/open-questions.md).
